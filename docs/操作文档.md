# Authright_Voting 操作文档

版本：v1.2 生产运维

更新日期：2026-09-26

状态：已部署到 AWS Lightsail，正式域名为 https://vote.authright.com；定时备份与站外恢复尚未在本次发布中配置或验收。详见[部署文档](部署文档.md)。

本文分为产品使用和技术维护两部分。现有生产环境的配置、镜像更新与回退步骤以[部署文档](部署文档.md)为准；下文首次部署段落保留为另建环境的参考。

## 1. 发起者：创建和分享投票

1. 打开起始页，点击“发起投票”。任何访问者都可以使用该入口，无需注册。
2. 输入投票标题，可选填活动说明。
3. 添加 2–8 个不同的选项。
4. 选择“立即开始”或预约开始时间，设置截止时间，检查页面显示的时区。
5. 核对内容，确认发布。发布后问题、选项和时间将锁定。
6. 发布成功后，保存“我的结果链接（私密）”，供自己随时查看统计。
7. 复制“投票链接”，或展示其二维码，发给参与者。

发布成功页提供两条链接：“投票链接”给参与者，“我的结果链接（私密）”由发起者保存。私密链接还具有本活动的管理权限，应只交给需要管理该活动的人。二维码始终对应投票链接。活动编号只用于查找活动。

目前点击“复制投票链接”得到的是完整 URL。粘贴到聊天窗口后是否生成带题目的预览卡片，由聊天平台和链接可访问性决定；项目目前尚未实现每场投票独立的分享卡片信息或自定义文字链接。局域网 `192.168.x.x` 链接只供同一网络中的设备打开。

发布请求失败或超时时，先使用原页面重试。应用应识别同一次发布，避免重复生成活动。

## 2. 参与者：投票和查看结果

1. 打开公开链接或扫描二维码。
2. 查看活动状态、截止时间和选项。
3. 若活动进行中，选择一个选项，点击“就选这个！”。提交后不能修改。
4. 等待服务器确认成功，查看当前总票数和各选项占比。
5. 保持页面打开时，当前结果约每 5 秒更新一次；活动结束后展示最终结果。

| 页面提示 | 含义与操作 |
| --- | --- |
| 投票尚未开始 | 等待页面显示的开始时间 |
| 你已投票 | 当前浏览器身份已经提交过，直接查看结果 |
| 投票已结束 | 活动到期或被提前关闭，可查看最终结果 |
| 提交结果确认中／网络异常 | 保留原页面，重试或刷新确认；系统应避免重复计票 |
| 操作过于频繁 | 等待提示时间后再试 |
| 活动不存在 | 核对链接是否完整，联系分享者 |

浏览器身份只用于基础防重复。换设备或清除浏览器记录后，系统可能无法识别之前的参与状态。

## 3. 发起者：查看统计和提前结束

1. 打开保存的私密管理链接。
2. 查看当前状态、总票数、各选项票数与占比、投票趋势。
3. 通过“复制投票链接”或二维码继续分享公开入口。
4. 需要提前结束时，点击“提前结束投票”，核对活动并确认。

提前结束立即停止接收新的有效投票，结果对所有访问者公开。第一版结束后不重新开放。

管理链接首次兑换成功后，浏览器通过管理会话继续访问。换设备时使用已保存的完整私密链接。

### 3.1 管理链接丢失或失效

1. 通过项目约定的人工渠道联系管理员，提供活动编号或公开链接以便定位。
2. 管理员结合已有沟通记录等信息核实归属，公开标题和活动编号本身不构成所有权证明。
3. 核实后，管理员重置管理链接并私下交付新的链接。
4. 发起者保存新链接；旧链接及旧发起者会话不再有效。

第一版没有自动找回功能。项目正式使用前应明确管理员联系人和联络方式，不能在页面中填入虚构联系方式。

## 4. 管理员：登录和全局管理

### 4.1 登录与退出

1. 打开 `/admin/login`。
2. 输入部署时初始化的管理员用户名和密码。
3. 登录后进入后台总览；使用完毕点击“退出登录”。

“管理员入口”只在网站首页页脚显示；创建页、投票页等不会显示，但仍可直接访问 `/admin/login`。不提供公开注册和默认密码。会话过期后重新登录。忘记管理员密码时，由拥有服务器权限的维护人员通过维护命令重置，并撤销旧管理员会话。

### 4.2 查找活动与历史记录

1. 打开“全部投票”。
2. 按标题或活动编号搜索。
3. 通过“未开始／进行中／已结束”筛选状态。
4. 需要历史归档时，将归档筛选切换为“全部”或“已归档”。
5. 进入活动详情查看问题、选项、起止时间和统计。

总览中的累计活动数和累计票数包含归档记录。默认列表收起已归档活动，记录仍然保留。

### 4.3 管理操作

| 操作 | 使用步骤 | 结果 |
| --- | --- | --- |
| 提前关闭 | 进入详情，点击“提前结束”，核对后确认 | 活动立即结束，结果公开，写入操作记录 |
| 归档 | 对已结束活动点击“归档活动”并确认 | 从默认列表收起，公开结果链接继续有效 |
| 取消归档 | 在已归档筛选中打开详情，点击“取消归档” | 恢复出现在默认列表 |
| 获取投票分享链接 | 在活动详情点击“获取投票分享链接”，再点击“复制分享链接” | 得到该活动的公开投票地址；不会改变管理链接 |
| 重置管理链接 | 核实请求者归属，点击“重置管理链接”并确认 | 新链接生成，旧链接及旧发起者会话失效 |
| 查询操作记录 | 打开“操作记录”，按时间翻页；单场详情显示最近操作 | 查看关闭、归档和重置等历史操作 |

重置后应及时复制新链接并私下交付，切勿将它作为公开投票链接转发。如果未保存新链接，可以再次重置；系统不提供读取原明文令牌的功能。

管理员可以查询统计，但界面不提供修改票数、替换选项或永久删除历史记录的操作。

## 5. 本地开发

以下命令已在本地验证。首次启动需要生成自己的 `VOTER_SECRET` 和管理员密码。

### 5.1 前置条件

- Node.js 24 和 npm；版本记录在 `.node-version`。
- 本地可以写入的数据目录。
- 验证容器部署时需要 Docker 与 Docker Compose。

仓库已包含 `.node-version`、`package-lock.json`、不含真实密钥的 `.env.example`。

### 5.2 配置项契约

| 配置项 | 用途与要求 |
| --- | --- |
| `APP_ORIGIN` | 应用的完整源地址；仅本机使用可设为 `http://127.0.0.1:3000`，局域网分享应设为本机局域网 IP（如 `http://192.168.1.10:3000`），正式环境使用真实 HTTPS 地址；用于分享链接、二维码和写入接口的同源校验 |
| `SQLITE_PATH` | 数据库文件路径；正式容器内建议 `/app/data/voting.sqlite` |
| `VOTER_SECRET` | 至少 32 字符的高熵随机值，用于匿名身份签名及身份摘要；更换会影响已有匿名身份 |
| `SITE_DOMAIN` | 部署时用于 Caddy 的真实域名，不包含协议前缀 |
| `BACKUP_DIR` | 备份输出目录，按实现确定容器内路径及宿主机挂载 |

管理员密码通过交互式初始化输入，不作为公开前端变量，也不写在命令行参数或源码中。管理员会话有效期 12 小时，发起者管理会话 30 天；登录限流为每来源 15 分钟 10 次，创建为每来源每小时 10 次，投票为每匿名身份每活动每分钟 8 次、每来源 IP 每分钟 120 次。阈值见 `src/app/api/`，会话设置见 `src/lib/security.ts`，限流计数在进程重启后清零。

### 5.3 实际命令

| 命令 | 作用 |
| --- | --- |
| `npm ci` | 按锁文件安装依赖 |
| `npm run dev` | 启动本地开发服务，并在就绪后自动预热投票接口 |
| `npm run dev:prewarm` | 开发服务运行期间手动重新预热投票接口；不会写入选票 |
| `npm run build` | 构建生产应用 |
| `npm run start` | 启动生产服务 |
| `npm run db:migrate` | 顺序执行尚未执行的 SQL 迁移；支持重复运行 |
| `npm run admin:init` | 交互式创建首个管理员；已存在时不静默覆盖 |
| `npm run admin:reset-password` | 交互式重置管理员密码并撤销旧管理员会话 |
| `npm run db:backup` | 使用在线备份机制生成一致性备份并执行完整性检查 |
| `npm run check` | 执行类型检查和静态检查 |
| `npm test` | 执行业务规则、权限及数据库一致性相关测试 |

首次运行顺序：

```bash
npm ci
cp .env.example .env.local
openssl rand -hex 32
```

将命令输出填入 `.env.local` 的 `VOTER_SECRET`，然后执行 `npm run db:migrate`、`npm run admin:init`、`npm run dev`。开发服务监听 `0.0.0.0:3000`；分享链接前等终端显示“投票接口预热完成”。`admin:init` 需要交互式终端，管理员密码至少 12 位。数据库默认保存在 `./data/voting.sqlite`。

要在同一局域网分享投票：查出运行机器的局域网 IP，设置 `.env.local` 中的 `APP_ORIGIN=http://该IP:3000`，重启开发服务；用这条地址打开网站并创建投票。即使发起者从 `127.0.0.1` 打开，生成的公开链接、私密链接和二维码也使用配置的局域网地址。IP 变化后必须更新配置并重启。确保参与设备在同一网络、本机防火墙允许 3000 端口，且路由器未开启客户端隔离。局域网 HTTP 不加密，正式公开部署请使用 HTTPS。

开发脚本固定使用 `3000`（或显式设置的 `PORT`）；如果已经有开发服务器占用该端口，先访问现有服务或自行停止旧进程，不要同时再启动一份。脚本在服务就绪后发起一次不会写入选票的请求以预热投票接口；修改接口后如需再次预热，运行 `npm run dev:prewarm`。这只改善开发模式首次请求的编译等待，不改变正式构建流程。

SQL 迁移文件约定保存在 `db/migrations/`，使用有序编号；已应用的迁移文件不直接改写，结构变更通过新迁移完成。

## 6. AWS 首次部署流程

以下是另建单实例环境的基础流程。现有站点已上线，使用 GitHub Actions 构建镜像并固定 digest 部署；更新现有站点请使用[部署文档](部署文档.md)，不要用这里的构建示例覆盖生产配置。

1. 创建一台 AWS Lightsail Linux 实例，选择适合使用者位置的区域。
2. 配置稳定公网地址，将域名解析到该地址。
3. 安装 Docker 与 Docker Compose，开放网站所需的 HTTP/HTTPS 端口，限制服务器管理访问。
4. 准备部署目录、持久化数据目录、备份目录，以及包含真实域名和密钥的私有配置。
5. 在服务器部署目录放置本项目文件，用 `docker compose` 构建应用镜像；构建阶段安装 SQLite 原生模块需要的编译工具。
6. 将宿主机数据目录挂载到 `/app/data`；同一个数据库只由一个应用实例使用。
7. 执行数据库迁移与管理员初始化。
8. 启动应用和 Caddy，由 Caddy 提供 HTTPS 并转发到应用。
9. 完成上线核验后启用定期数据库备份、站外备份和实例快照。

部署目录中先复制 `.env.example` 为 `.env.production`，设置 `APP_ORIGIN=https://你的域名`、`SITE_DOMAIN=你的域名` 和随机的 `VOTER_SECRET`。域名不带协议；不要把 `.env.production` 提交到仓库。Caddy 需要 80/443 端口可用，域名 DNS 应先指向该实例。

```bash
docker compose config --quiet
docker compose up -d --build app
docker compose exec app npm run admin:init
docker compose up -d caddy
```

容器启动时自动执行迁移。若管理员已存在，不要再次运行 `admin:init`；需要修改密码时运行 `docker compose exec app npm run admin:reset-password`。`./data`、`./backups` 分别挂载至容器 `/app/data`、`/app/backups`。构建时使用 Node 24 Linux 镜像，本地 macOS 的 `node_modules` 不会复制进去。

数据库目录需要允许应用运行用户读写。密钥文件仅授予必要账户读取权限；应用数据与日志分开保存。

### 6.1 上线核验

- HTTPS 可访问，分享链接使用正式域名。
- 创建一场测试投票，在独立浏览器中完成投票并查看结果。
- 原浏览器重试不增加票数，另一匿名身份可正常投票。
- 未投票身份访问进行中结果接口时拿不到票数。
- 到期和提前关闭后无法投票，最终结果可以公开查看。
- 管理员能搜索活动、查看统计、归档并找回记录。
- 重置管理链接后，旧链接和旧管理会话都不能继续管理。
- 重启应用后，活动、票数、管理员及操作记录仍然存在。
- 成功生成备份，并在隔离环境验证恢复。

## 7. 更新应用与故障回退

当前生产环境的可执行步骤、镜像版本和本次发布记录见[部署文档](部署文档.md)。

1. 先在本地或隔离环境完成检查、构建和相关测试。
2. 保存当前镜像版本和部署配置，生成一次经过验证的数据库备份。
3. 若涉及数据库迁移，安排短暂维护窗口，在暂停应用写入后执行迁移。
4. 使用新镜像启动单个应用实例。
5. 核验登录、创建、投票、统计和历史记录；确认后恢复正常使用。

更新应用时保留持久化数据目录，不执行会删除数据卷的清理操作。部署配置应明确区分镜像文件和业务数据。

需要回退时，先判断旧应用是否兼容当前数据库结构。若兼容，可恢复旧镜像；若必须恢复旧数据库，应先停止写入并额外保存当前数据库，明确备份之后的新活动和选票需要另行处理，不能直接覆盖丢弃。

## 8. 备份与恢复

### 8.1 日常备份

建议每天自动备份，保留最近 7 份日备份和 4 份周备份；活动集中进行时可以提高频率。升级前额外备份，并至少保留一份服务器之外的副本。

运行 `docker compose exec -T app npm run db:backup` 生成一致性备份并执行完整性检查，文件写入宿主机 `./backups`。WAL 模式下，不要在运行中只复制 `.sqlite` 主文件作为可靠备份。项目只提供备份命令；定时运行、保留清理、站外复制和失败通知需要在服务器另行配置。

每份备份应记录生成时间、应用版本、数据库迁移版本及完整性检查结果。备份包含选票和身份摘要，存储访问权限应与正式数据库同等保护。

部署配置及密钥另行安全保存。数据库备份不能替代密钥备份，实例快照也不能替代已验证的数据库恢复流程。

### 8.2 恢复步骤

1. 确定需要恢复的时间点，停止应用及其他数据库写入者。
2. 单独保存当前数据目录、日志和配置以便排查。
3. 在隔离目录恢复选定备份，执行完整性检查并核对数据库版本。
4. 使用与备份结构兼容的应用版本，检查活动数、选票数及管理员数据。
5. 通过受控切换替换正式数据目录，核对权限；避免混入旧数据库的 WAL/SHM 文件。
6. 恢复所需密钥与配置，撤销恢复出来的旧登录会话。
7. 启动应用，核对公开结果和后台操作，再恢复访问。

恢复到过去的时间点也会回退管理链接的重置记录。对于受影响的活动，应重新核实并重置管理链接，避免旧权限重新有效。

## 9. 常见问题排查

| 问题 | 优先检查 |
| --- | --- |
| 网站无法访问 | 域名解析、实例运行状态、开放端口、Caddy 和应用日志 |
| HTTPS 未生效 | 域名是否解析到本实例，证书申请所需网络是否可达 |
| 投票失败 | 活动时间、是否已关闭、匿名身份是否已投、限流提示、数据库写权限 |
| 票数没有变化 | 是否重复请求、页面上次更新时间、统计请求是否失败、实际选票是否写入 |
| 数据库忙或锁等待超时 | 是否存在第二个应用实例、过长事务、异常维护进程；不要直接删除锁相关文件 |
| 重启后数据消失 | 数据目录是否正确持久化、是否使用了新的空数据库路径 |
| 管理链接失效 | 链接是否完整、是否已重置、管理会话是否过期 |
| 管理员无法登录 | 用户名、密码、会话配置和限流；必要时通过维护命令重置密码 |
| 备份失败 | 可用磁盘、目标目录权限、备份机制与检查结果、站外复制状态 |
| 手机出现 Next.js hydration 报错弹层 | 先刷新并记录开发日志中的具体差异。已针对内置浏览器给根 `<html>` 注入属性或样式的情况做定点兼容；若差异出现在页面内部组件，应继续定位对应组件，不要直接隐藏全部报错。生产构建不会显示开发模式报错弹层。 |
| 分享到聊天时仍显示 URL | 当前复制按钮只复制 URL；标题分享卡片尚未实现。局域网 IP 对外部预览服务不可达，正式分享效果需在确定目标平台和公网域名后验证。 |

排查和收集日志时，不粘贴管理员密码、私密管理链接、会话 Cookie 或部署密钥。
