GitHub Actions 负责检查、测试、构建并上传镜像；**不会自动更新服务器**。日常发布只更新 `app`，不需要重启 Caddy 或重新创建管理员。

服务器的 `compose.yml` 包含固定版本镜像、健康检查、日志轮转和持久化挂载。仓库根目录的 `compose.yml` 是本机构建示例，**不要直接覆盖生产文件**。

生产应保留 `APP_ORIGIN=https://vote.authright.com`、已有 `VOTER_SECRET`、`SQLITE_PATH=/app/data/voting.sqlite` 和 `BACKUP_DIR=/app/backups`。不需要因普通版本更新而更换密钥。

## 2. 连接服务器

使用 Lightsail 浏览器 SSH 终端，或在自己的终端执行：

```bash
ssh -i /你的私钥路径/LightsailDefaultKey-us-east-1.pem admin@44.195.22.238
```

首次连接通过可信渠道核对服务器指纹；之后使用已经信任的主机记录。不要在聊天、文档或 Git 中粘贴私钥、管理员密码或 `.env.production` 内容。

连接成功后，下文命令均在服务器的同一 Bash 会话中执行：

```bash
cd /opt/authright-voting
docker compose ps
```

## 3. 发布更新

### 第一步：确认镜像构建成功

本地提交并推送代码到 `main` 后，打开 [Publish Docker image 工作流](https://github.com/TAO44123/Authright_vote/actions/workflows/publish-image.yml)。

找到待发布提交对应的运行，确认绿色成功。工作流依次执行 `npm ci`、`npm run check`、`npm test`、Docker 构建和镜像上传。镜像同时标记完整 Git 提交 SHA 与 `latest`。

复制这一次运行的完整提交 SHA。生产更新使用这个明确版本，不直接追随可能变化的 `latest`。

### 第二步：保存回退配置并备份数据库

```bash
umask 077
RELEASE_DIR="private/release-$(date -u +%Y%m%dT%H%M%SZ)"
mkdir "$RELEASE_DIR"
cp -p compose.yml Caddyfile .env.production DEPLOYMENT.md "$RELEASE_DIR/"
docker compose images --format json > "$RELEASE_DIR/images-before.json"
docker compose exec -T app npm run db:backup
```

**只有备份命令成功并输出“通过完整性检查”后才能继续。** 记录输出的备份文件名与 `RELEASE_DIR`。这是 SQLite 在线一致性备份，不要在数据库运行时只复制 `.sqlite` 主文件。

### 第三步：拉取指定镜像，固定到 digest

把下面的占位文字替换为第一步确认成功的完整 SHA：

```bash
RELEASE_SHA='替换为40位Git提交SHA'
docker pull "ghcr.io/tao44123/authright_vote:$RELEASE_SHA"
export IMAGE_REF=$(docker image inspect \
  "ghcr.io/tao44123/authright_vote:$RELEASE_SHA" \
  --format '{{index .RepoDigests 0}}')
printf '%s\n' "$IMAGE_REF"
```

如果仓库镜像被改为私有，需要先用具备读取该包权限的账号登录 `ghcr.io`；使用交互式登录或 `--password-stdin`，不要把令牌写入文档、Git 或命令行参数。

确认镜像地址正确后，仅替换生产 Compose 中的应用镜像：

```bash
python3 - <<'PY'
import os, re
from pathlib import Path
image = os.environ['IMAGE_REF']
assert re.fullmatch(r'ghcr\.io/tao44123/authright_vote@sha256:[0-9a-f]{64}', image)
p = Path('compose.yml')
text, count = re.subn(
    r'(?m)^(    image: )ghcr\.io/tao44123/authright_vote[^\s]*$',
    lambda m: m[1] + image,
    p.read_text(),
)
assert count == 1, '应用镜像行与预期不符；停止并人工检查'
p.write_text(text)
PY
docker compose config --quiet
```

如果校验失败，先恢复本次备份的 `compose.yml`，不要执行更新。涉及新的数据库迁移时，应在切换前确认迁移与回退兼容性，并根据需要安排暂停写入的维护窗口。

### 第四步：替换应用容器

```bash
docker compose up -d --no-deps --wait --wait-timeout 120 app
docker compose ps
docker compose logs --tail=80 app
```

`app` 应显示 `healthy`，日志中应看到迁移完成和应用启动成功。容器启动时会执行尚未应用的迁移；更换容器期间会有短暂访问中断。若启动或验证失败，执行下一节的回退。

### 第五步：验证并记录

```bash
curl --fail --silent --show-error https://vote.authright.com/api/config
```

输出中的 `origin` 应为 `https://vote.authright.com`。此外：

- 打开首页、创建页和后台登录页，检查本次修改。
- 用手机分别检查立即开始与预约开始时的时间框。
- 登录后台，确认已有投票、选票和管理员仍可访问。
- 检查已有投票的公开页、结果页和二维码。
- 需要验证创建、投票等写入流程时，使用明确标注的测试活动，完成后关闭并归档；不要修改真实活动的选票。

发布完成后在发布记录中保存提交 SHA、镜像 digest、配置备份目录、数据库备份路径和验证结果，并更新服务器 `DEPLOYMENT.md` 中的当前版本。

## 4. 回退应用

以下适用于数据库仍与旧应用兼容的情况。本次 `dbbfb30` 仅修改界面与文案，迁移文件与前一版本一致。

```bash
cd /opt/authright-voting
# 改为这次发布实际保存的目录，不要猜测目录名。
RELEASE_DIR='private/本次发布备份目录'
cp -p "$RELEASE_DIR/compose.yml" compose.yml
docker compose config --quiet
docker compose up -d --no-deps --wait --wait-timeout 120 app
curl --fail --silent --show-error https://vote.authright.com/api/config
docker compose ps
```

这只回退应用版本，保留当前数据库。若更新包含不兼容迁移，不要直接回滚或覆盖数据库；先停止写入、保存现有数据，再制定恢复方案，避免丢失备份之后的投票。更新或回退均不要运行 `docker compose down -v`。

## 5. 常用维护命令

```bash
cd /opt/authright-voting
# 服务状态

# 交互式重置管理员密码，仅在确实需要时执行
```

定时备份、站外备份和恢复演练尚未在本次发布中配置或验收。服务器内的发布备份不能替代站外副本。
